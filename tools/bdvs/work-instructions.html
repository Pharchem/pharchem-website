Production: register, upload, hand over

A · Every evening — Daily Production & Dispatch Register (Google Sheet)

  1. Open the register sheet (bookmark on the department computer / phone).
  2. Add one row per batch manufactured today: Mfg Date, Batch No. (e.g. ALP/214(26-27)), Customer. Product and Batch Size may be left blank.
  3. No production today? Add one row: today's date, Batch No. = NIL.
  4. When a batch is dispatched, fill Dispatch Date and Invoice / Challan No. on that batch's existing row. Never add a second row for the same batch.
  5. Always write the customer's name the same way (e.g. "Dynemic Products Ltd").
  6. Do not touch the BDVS Status column — the system writes there at 8 PM. A row marked ERROR: must be corrected the same evening or next morning.

B · Within 2 days of dispatch — upload the filled BMR/BPR

  1. Scan the complete filled BMR/BPR: every page in order, including index, dispensing slips, IPQC checklist and all attachments. Check each page is legible.
  2. Log in to BDVS with your own username → My tasks → Upload scan on the batch.
  3. Attach the PDF (or phone photos — they are combined automatically). Enter the total page count, counted from the physical document.
  4. Type the values recorded in the document exactly as written (pH, pressure, yield…). Write NR only if the value is genuinely not recorded.
  5. Fill the document details (mfg date, expiry, challan), tick all five checklist boxes, press Upload.

C · If QA rejects — and after Verified OK

  1. Rejected: open the task → See observations (page, severity, what is wrong) → correct the original as per GDP (single line, initial, date, reason) → Re-upload corrected scan. The old version stays on record.
  2. Verified OK: press Print transmittal slip, attach it to the original hardcopy, and hand it to QA within 3 working days.
If something goes wrong
Forgot password / account lockedAsk the administrator to reset / unlock. Never use a colleague's login.
Upload refused: "page count mismatch"Recount the physical pages; rescan missing pages.
Scanner downUse phone photos — straight on, all 4 corners visible, good light.
Deadline will be missedInform QA before the deadline; reminders escalate to management automatically.

QC: upload the COA with raw data

A · Within 2 days of dispatch — upload COA + raw data

  1. Assemble the complete analytical record for the batch: COA, raw data sheets / analytical protocols (chemical bulk & finished, microbial), instrument printouts, calculations.
  2. Scan everything in order; check each page is legible, including printouts.
  3. Log in to BDVS with your own username → My tasks → Upload scan on the batch.
  4. Attach the PDF(s), enter the total page count counted from the physical record.
  5. Type the test results exactly as on the COA (pH, solid content, assay, lead…). Write NR only if a result is genuinely not recorded. An out-of-specification entry does not block the upload — it alerts QA, as it should.
  6. Fill the document details (batch no. as printed, dates, customer), tick the checklist, press Upload.

B · Outside / pending test reports (e.g. lead content)

  1. If an outsourced result is still pending at upload, note it in Remarks and on the COA as per practice.
  2. When the report arrives, give it to QA for the batch file; QA records the reference in the system.

C · If QA rejects — and after Verified OK

  1. Rejected: open the task → See observations → correct per GDP → Re-upload corrected scan (new version; nothing is deleted).
  2. Verified OK: Print transmittal slip and hand the original COA + raw data to QA within 3 working days.
If something goes wrong

The form does not ask for a test you reportTell QA to add it under Settings → Limits.

Chromatogram / printout illegible in scanRescan at higher quality before uploading.

QA: verify, receive hardcopy, close

A · Every morning

  1. Open the Dashboard: red "Day" chips and overdue counts first. Chase anything past Day 2.
  2. Open the Verification queue — every upload must be decided within 24 working hours (Sundays/holidays excluded).
  3. Check last evening's register email: correct ERROR rows with Production; for a new customer, open the batch → Change master documents if the auto-match is wrong (it is remembered).

B · Verifying a document

  1. Open Verify: scan on the left; batch data, master documents and the Automatic check on the right.
  2. Work through the automatic check first: OUT OF LIMIT needs a Deviation/OOS no. (QAGE/025) + justification before acceptance; out-of-trend, date and cross-check flags need a written justification; misread/NR values — read the scan and press Correct.
  3. Answer every checklist item against the scan (N/A needs a reason). "No" on any item means Reject.
  4. Accept, or Reject with page-wise observations (page, text, severity). Enter your password — it is your signature.

C · Hardcopy and closure

  1. On receipt: count pages against the verified scan, record condition and storage location (rack/file). A mismatch becomes a discrepancy and blocks closure until resolved.
  2. When both documents are verified and both originals received: open the batch → Complete Batch Data Verification (password). The record locks.

D · Housekeeping (weekly / as needed)

  1. Add declared holidays in Settings (keeps the 24-h and 3-day clocks honest).
  2. After any master BMR/STP/COA format change in the GMP folder: Settings → Scan GMP folder, then review & approve the new limits.
  3. Check the Sunday backup email says SUCCESS; raise anything else with the administrator the same day.
  4. 1st of the month: review the limits & trend report email (APQR input).
